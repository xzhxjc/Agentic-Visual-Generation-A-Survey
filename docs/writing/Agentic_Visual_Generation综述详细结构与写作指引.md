## 0. 本文档的用途

本文档用于指导后续综述写作，不是最终论文正文。所有成员应使用同一套定义、分类、术语和证据标准，避免出现以下问题：

1. 将综述写成逐篇论文简介的集合。
2. 将“multi-agent”“多轮生成”或“模块较多”直接等同于 Agentic。
3. 同一篇论文在图像、架构、闭环等多个章节重复介绍。
4. 只讨论最终图像质量，而忽略规划、工具调用、反馈、停止和成本。
5. 将预印本结果与已同行评审论文视为同等强度的证据。
6. 将 Agentic Visual Generation 扩展成无边界的视觉生成、视觉 Agent 或世界模型综述。

写作时应优先使用以下本地材料：

## 1. 论文的总体定位

### 1.1 推荐标题

英文主标题建议：

> **Agentic Visual Generation: A Survey of Planning, Tool Use, Feedback, and Self-Improvement in Visual Creation**

可选标题：

> **From Visual Generation Pipelines to Goal-Directed Visual Agents: A Systematic Survey**

> **Agentic Visual Generation: Taxonomy, Architectures, Evaluation, and Open Challenges**

中文工作标题：

> **Agentic Visual Generation：面向视觉创作的规划、工具调用、反馈闭环与自我改进综述**

标题应同时体现“视觉生成”和“Agentic”，避免只写 Visual Agents，因为后者通常还包含视觉问答、导航、GUI 操作和机器人控制等大量非生成任务。

### 1.2 贯穿全文的中心命题

全文必须围绕以下命题展开：

> 视觉生成正在从一次性的输入输出映射，转变为由目标驱动、能够理解与规划、编排与执行、观察与验证、反馈与修正，并进一步积累经验和自我改进的闭环决策过程。

这意味着视觉生成器不再等同于完整系统。生成器只是 Agent 可调用的一种动作执行器；完整系统还包括目标、状态、观察、决策、记忆、验证、环境反馈和终止机制。

### 1.3 本文需要建立的五个核心判断

1. **Agentic 的本质是对生成轨迹的决策自主性，而不是模块数量或对话轮数。**
2. **当前领域的主流仍是工具和角色编排，而不是稳定的长程自主生成。**现有核心集合中，工具/协作辅助工作明显多于长程自主工作。
3. **视觉反馈和可执行验证是该领域区别于一般 LLM Agent 的关键。**视觉产物必须被重新观察，并通过语义、空间、身份、几何、物理、数据或功能约束验证。
4. **不同视觉模态的主要差异不是生成模型名称，而是状态表示、动作空间和验证机制。**
5. **未来瓶颈不只是更强的渲染器，还包括可靠验证、长期状态、动态控制、成本效率、统一评测和持续学习。**

### 1.4 预期学术贡献

本文应明确宣称并实际完成以下贡献：

1. 提出 Agentic Visual Generation 的操作性定义、必要条件和边界判定规则。
2. 提出以 Agent 在视觉生成闭环中的位置为主轴的统一分类法。
3. 将视觉模态、Agent 架构、Agentic 能力和自主性作为正交的辅助分析轴。
4. 系统分析 264 篇文献，并区分核心、邻接和支撑证据。
5. 建立同时覆盖视觉产物、目标满足、Agent 轨迹和系统属性的四层评测框架。
6. 基于定量分布和方法比较，提出从工作流编排走向视觉原生 Agent 的研究议程。

### 1.5 本文不应承担的任务

1. 不完整回顾 GAN、扩散模型、流模型和自回归模型的发展史。
2. 不将所有多模态 Agent、GUI Agent、机器人 Agent 和世界模型纳入主体。
3. 不按图像、视频、3D 顺序重复介绍相似的规划、工具和反馈方法。
4. 不把所有带有 Agent 名称的论文视为严格意义的 Agentic 系统。
5. 不对尚无可重复证据的封闭系统内部机制作确定性判断。

## 2. 研究问题

### RQ1：什么是 Agentic Visual Generation？

需要回答其操作性定义、必要条件、范围和边界，并区分普通视觉生成、固定工作流、Agent-augmented workflow、动态闭环 Agent、视觉理解 Agent与世界模型。

### RQ2：视觉生成何时从工作流变成闭环 Agent？

需要分析目标理解、规划、执行、视觉观察、验证、修正、回滚和终止之间是否构成状态依赖的决策闭环，而不是只统计模块或角色数量。

### RQ3：闭环由哪些机制实现，当前证据主要集中在哪里？

以“理解与规划—行动与执行—观察与验证—反馈与终止—记忆与学习”为主线，比较系统能看到什么、能做什么、何时改变行动。架构、多 Agent、工具和自主性只作为解释这些机制的横向维度。

### RQ4：不同视觉模态如何改变状态、动作和验证？

比较图像、视频/动画、3D/CAD/世界、科学图表、结构化视觉文档/演示文稿以及 UI/Web 任务的状态表示、动作空间、验证器和长程失败模式；避免按模态重复介绍同一类规划或编排机制。

### RQ5：如何证明闭环 Agent 真正有效，下一步缺少什么？

建立产物、约束、轨迹和系统四层评测视角，结合当前文献的评测、消融、成本和发表证据，说明可靠验证、长程状态、动态终止和持续学习为何仍是主要瓶颈。

## 3. 定义、边界与统一形式化

### 3.1 工作定义

建议在正文中使用以下定义：

> Agentic Visual Generation 是指面向图像、视频、3D、CAD、图表、文档、UI 或其他视觉产物的生成与编辑系统。系统围绕用户或环境给定的目标，根据当前观察、历史状态和可用工具，自主选择规划、检索、生成、编辑、验证、修正或终止等动作，使视觉产物经过一个或多个决策步骤逐渐满足目标。

该定义包含三个最低要求：

1. 目标中必须包含视觉产物的生成、编辑、构建或组合。
2. 系统中必须存在可识别的决策主体，而不只是固定模块串联。
3. 决策行为必须实质性影响视觉生成轨迹或最终产物。

### 3.2 严格 Agentic 的四个判据

对于严格意义的 Agentic 系统，应进一步检查：

1. 是否依据观察动态决定下一动作，而非始终执行预设步骤。
2. 视觉输出是否改变环境或任务状态，并影响后续输入。
3. 是否跨多个步骤持续追求同一长程目标。
4. 是否能够自主决定继续、回滚、重规划或终止。

满足最低要求但不满足全部严格判据的工作仍可进入广义正文，但必须标记为 Agent-augmented workflow，而不能与严格 Agent 等量表述。

### 3.3 统一闭环形式化

设任务目标为 (g)，环境状态为 (s_t)，当前视觉产物为 (x_t)，记忆为 (m_t)，可调用工具集合为 \(\mathcal{T}\)。Agent 首先获得观察：

\[
o_t=P(s_t,x_t),
\]

然后根据目标、观察、记忆和工具选择动作：

\[
a_t=\pi_{\theta}(g,o_t,m_t,\mathcal{T}).
\]

动作可以是规划、搜索、模型路由、提示修改、代码执行、生成、编辑、验证、回滚或终止。视觉生成器或外部工具执行动作：

\[
x_{t+1}=G(x_t,a_t;\tau_t),
\]

其中 \(\tau_t\) 表示被选择的模型、工具或参数。环境与记忆随后更新：

\[
(s_{t+1},m_{t+1})=U(s_t,m_t,a_t,x_{t+1},o_t).
\]

终止策略：

\[
z_t=\delta(g,s_t,x_t,m_t), \qquad z_t\in\{\text{continue},\text{replan},\text{rollback},\text{stop}\}.
\]

该形式化用于统一解释不同模态。不同论文的差异可以归结为：状态如何表示、能观察什么、允许采取什么动作、由谁评价、反馈如何更新策略，以及终止条件是否动态。

### 3.4 三层范围

| 范围 | 定义 | 在正文中的作用 |
|---|---|---|
| 核心（168篇） | Agent 对规划、工具、验证、迭代或学习有实质作用，并直接影响视觉生成轨迹或产物 | 构成方法分类和主要综合；内部再用 L2–L5 区分 Agent-augmented workflow 与严格闭环 Agent |
| 邻接（69篇） | 与视觉生成密切相关，但 Agentic 决策较弱、任务边界相邻或主要承担对照作用 | 用于边界、相关任务和历史比较，不与核心等量统计 |
| 支撑（27篇） | 普通生成底座、Agent 方法论、世界模型、评测、安全和数据工作 | 用于背景、评测和未来方向，不作为核心方法数量的一部分 |

### 3.5 自主性等级

本文统一使用 L1–L5 表示控制与证据层面的自主性连续谱：

| 等级 | 名称 | 判定标准 |
|---|---|---|
| L1 | 固定映射/固定流程 | 一次输入输出，或控制路径完全预设 |
| L2 | 工具与角色辅助 | 可以选择工具、模型或角色，但缺乏稳定反馈闭环 |
| L3 | 反馈适应 | 会观察中间视觉结果，并据此进行一次或多次修正 |
| L4 | 长程自主 | 具备长期状态、动态重规划、失败恢复和自主终止 |
| L5 | 持续自我改进 | 能跨任务积累经验，并持续更新记忆、策略、技能或模型 |

L1 一般只作为背景或对照。L2–L5 与“单 Agent/多 Agent”无直接对应关系；多 Agent 系统可能仍然只有 L2 自主性。

检索式应由“Agentic 词族 × 视觉任务词族 × 行为词族”组成。

附录中保存完整检索式、检索日期和平台结果数量，保证后续能够更新。

### 4.3 纳入标准

1. 最终目标或关键中间目标包含视觉内容的生成、编辑、构建或组合。
2. 系统存在承担规划、选择、调用、评价、修正或学习职责的 Agent。
3. Agent 行为会改变生成过程、视觉状态或最终结果。
4. 论文提供足够的方法和实验信息以进行技术分析。
5. 能获得正式全文或作者公开的可信版本。

### 4.4 排除或降级标准

1. 纯视觉理解、问答、导航或机器人控制，且视觉生成不是核心任务。
2. 仅在标题或模块名称中出现 Agent，实际没有决策行为。
3. 完全固定的多阶段流水线，且没有状态依赖的动作变化，应降为邻接或 L1。
4. 多智能体 GAN 等早期“agent”概念与现代 Agentic AI 不同，可作历史背景，但不与现代 LLM/MLLM Agent 混合统计。
5. 新闻、产品博客、演示页面和无技术细节的项目说明不能作为核心论文证据。

### 4.6 编码字段

至少保留以下字段：论文标识、题名、作者、年份、venue、发表状态、范围、模态、任务、主要生命周期位置、次要生命周期标签、架构、方法家族、Agentic 能力、自主性、训练方式、数据集、指标、基线、消融、开源状态、局限性、证据页码、编码者和复核者。

### 4.7 证据质量分级

建议将论文证据分为：

- E1：已同行评审、实验完整、代码或数据公开、结果可复现；
- E2：已同行评审，但代码、数据或关键设置不完整；
- E3：预印本，方法与实验相对完整；
- E4：预印本或技术报告，实验有限或关键机制不可验证。

证据等级不用于判断论文“好坏”，而用于控制综述结论的措辞强度。

## 5. 修订后的完整论文结构

### 5.1 结构设计原则

第3章保持不变，继续建立全文唯一的 Agentic Visual Generation 闭环坐标系；第4章改为全文的主要证据主体，按视觉模态和生成对象拆分为读者可以直接定位的方向章节。这样既保留“目标—行动—观察—反馈—记忆”的统一分析框架，又能清楚回答不同视觉产物中的 Agentic 机制到底如何落地。

正文的组织关系是：第3章回答“闭环由哪些环节组成”，第4章回答“这些环节在图像、视频、3D/CAD、科学图表、结构化文档和 UI/Web 中分别如何实现”，第5章回答“如何跨模态判断闭环是否有效”。模态、架构、Agentic 能力和自主性仍是横向标签，但不再取代模态章节的主体叙事。

该结构与现有语料分布相符：168篇核心论文中，图像与视频共133篇；生成中编排与执行87篇，反馈迭代37篇，学习与自我改进14篇，独立以生成后验证为主的只有5篇；多 Agent 相关架构约96篇，但长程自主仅7篇。因此，第4章应在充分覆盖各模态的同时，持续指出“编排占主导、验证和长期自主不足”这一跨模态现象。

### Abstract

摘要不编号，围绕一个判断组织：视觉生成的关键变化不只是生成器更强，而是系统开始在生成过程中进行目标理解、行动选择、视觉观察、验证和修正。

摘要应包含六个信息单元：

1. 背景：复杂视觉创作已超出一次提示、一次采样的能力边界。
2. 缺口：现有生成综述缺少闭环决策视角，现有 Agent 综述又忽略视觉状态、生成器和可验证约束。
3. 定义：给出 Agentic Visual Generation 的操作性定义与边界。
4. 语料：说明本文组织264篇可得全文，其中168篇核心论文用于主要综合，69篇邻接与27篇支撑论文用于边界、背景和评测。
5. 发现：当前领域以工具和多角色编排为主，可靠验证、动态终止、长程状态和持续学习证据仍不足。
6. 贡献：提出闭环框架、按视觉模态组织的核心综述、跨模态比较、四层评测视角和研究立场。

### 1. Introduction: Why Visual Generation Needs a Control Loop

#### 1.1 From a Generator to a Creation System

从复杂创作任务切入，而不是从生成模型历史切入。用组合图像编辑、长视频制作、CAD设计或科学图表为例，指出任务不仅要“生成”，还要理解目标、保持状态、调用工具、检查结果和处理失败。

#### 1.2 The Central Tension

提出全文张力：多数近期系统已经拥有多个模型、角色和步骤，但这不自动等于 Agentic。真正的问题是视觉结果是否作为观察改变下一步行动，系统是否能重规划、回滚或停止。

#### 1.3 What Existing Surveys Miss

用一张相关综述比较表说明：视觉生成综述通常按模型、任务或模态组织；Agent综述通常按规划、记忆和工具组织。两者都没有把“视觉状态—动作—验证—反馈”的闭环作为中心分析对象。

#### 1.4 Scope and Contributions

简要说明264篇可得全文和168篇核心论文的范围，详细检索记录置于附录。随后给出本文贡献：闭环定义、机制分析、按六类视觉模态组织的核心综述、跨模态矩阵、评测框架和以证据为依据的研究立场。

### 2. From Visual Pipelines to Closed-Loop Visual Agents

本章建立全文唯一的坐标系，回答“什么情况下可以称为 Agentic Visual Generation”。

#### 2.1 Operational Definition and Boundary

给出三个最低条件：视觉产物的生成、编辑或构建是任务核心；存在可识别的决策主体；该主体的决策实质影响生成轨迹或最终产物。明确排除纯视觉理解、没有状态依赖决策的固定流水线，以及仅在名称中出现 Agent 的工作。

#### 2.2 Workflow-to-Agent Continuum

以 L1–L5 作为成熟度标签，而非第二套方法分类：L1固定映射或固定流程，L2工具/角色辅助，L3基于中间结果的反馈适应，L4长程状态、重规划、恢复与自主终止，L5跨任务持续改进。重点说明多 Agent 或多轮交互都不是高自主性的充分证据。

#### 2.3 A Unified Agentic Visual Generation Loop

给出目标 g、状态 s、当前视觉产物 x、观察 o、记忆 m、动作 a、工具集合 T 和终止策略 z 的统一形式化。形式化的用途是比较不同论文的状态表示、动作空间、验证方式和停止机制，而不是制造抽象公式。

#### 2.4 Reading Guide for the Rest of the Survey

说明后文如何使用多轴标签：闭环阶段是正文主线；视觉模态解释任务差异；架构解释协作和控制流；能力与自主性用于横向统计；发表状态和PDF核验状态约束结论强度。

### 3. Operating the Agentic Visual Generation Loop

这是全文最长、最核心的一章。每一节统一回答五个问题：Agent 当前看到了什么？可采取什么动作？调用哪些生成器、工具或验证器？什么反馈会改变下一步？系统何时停止或升级行动？

#### 3.1 Goal Understanding and Visual Planning

讨论需求澄清、用户偏好、任务分解、对象/属性/关系表示、布局、故事板、镜头和CAD操作规划，以及检索外部知识。核心矛盾是 plan–render gap：语言或结构计划可能合理，但下游生成器并不能忠实执行。这里以生成前理解与规划的25篇核心论文为主要证据，并用图像组合、视频叙事和CAD约束对比计划表示。

#### 3.2 Acting: Model, Tool, Code, and Multi-Agent Orchestration

这是当前最大的方法簇，对应87篇以生成中编排与执行为主要位置的核心论文。讨论模型路由、工具/API调用、代码与可执行工作流、角色分工、多 Agent 协作和视觉原生生成 Agent。

架构比较嵌入本节，而不另设独立大章：单 Agent适合集中规划或工具调用；多 Agent适合角色分工、并行探索和跨专业工具链；层级编排适合复杂任务分解；生成者—批评者结构适合把评价反馈接回行动。必须区分真正的条件分支/状态依赖控制与固定角色流水线，并报告多 Agent 收益是否来自专门化、并行性，还是仅来自更多调用预算。

#### 3.3 Observing, Diagnosing, and Verifying Visual States

讨论视觉观察、质量评价、语义/空间/身份/文本验证、几何/物理/编译验证和人工反馈。现有核心论文中仅5篇主要定位于生成后观察与验证，这种稀缺本身是重要发现：领域普遍会“生成和编排”，却较少可靠地知道结果是否真的满足目标。

这里要严格区分：美学 critic 给出偏好分数；诊断器定位失败原因；verifier 检查可执行约束；只有评价结果改变后续行动时，才构成闭环证据。

#### 3.4 Revising, Replanning, Recovering, and Stopping

讨论局部编辑、提示/参数修正、候选搜索、重规划、回滚、失败恢复、成本感知决策和终止策略。37篇以反馈迭代为主要位置的论文是这一节的核心证据。重点不是“迭代次数更多”，而是中间视觉状态能否触发不同的修正策略，系统是否能在无改进、预算耗尽或约束满足时合理停止。

#### 3.5 State, Memory, and Self-Improvement

将短期视觉历史、角色/场景状态、工具轨迹、经验检索、测试时搜索、偏好优化、强化学习和持续学习统一在“跨步骤或跨任务改变策略”的问题下。由于仅14篇论文以学习与自我改进为主要位置，本节应避免夸大成熟度；应重点讨论奖励投机、经验迁移、错误记忆、训练成本和可重复性。

#### 3.6 Interim Position: Orchestration Is Not Yet Autonomy

用本章证据得出第一个核心立场：当前领域最成熟的是执行编排和多角色协作，反馈、验证、终止和跨任务学习仍明显不足。因此，大量系统更适合称为 Agent-augmented workflows，而不是稳定的长程视觉 Agent。

### 4. Agentic Visual Generation Across Visual Modalities

本章是全文的主要核心内容。第3章已经定义闭环阶段，因此本章不再按“规划、执行、验证”重复排列，而是按照视觉模态和最终生成对象分别展开，说明同一闭环在不同任务中的具体形态、方法家族、证据和瓶颈。每个模态小节都必须覆盖：任务目标与约束、Agent 所处的闭环位置、状态表示、可选动作、生成器/工具/验证器、反馈与终止机制、代表性实验结果以及局限性。

每个小节内部按方法家族组织，而不是逐篇罗列论文。论文只作为支撑某个机制、对比某种设计或说明某项结果的证据。章节开头先界定该模态为什么需要 Agentic 控制，随后按“理解/规划—编排/执行—观察/验证—反馈/恢复—记忆/学习”追踪方法，结尾给出该模态的综合判断，并标注核心论文数量、证据强度和主要空白。

#### 4.1 Agentic Image Generation and Editing

以71篇图像相关核心论文为主要证据，覆盖文本到图像、组合生成、参考图驱动、局部/多轮编辑、身份保持和布局控制。重点比较：

- 目标如何表示为对象、属性、空间关系、风格、身份和局部编辑约束；
- Agent 如何进行提示分解、模型/工具路由、候选搜索、掩码编辑、重采样和局部重绘；
- 当前图像状态、对象关系、掩码和编辑历史如何被观察并写回下一步决策；
- 语义、空间、身份、文本和美学验证器是否真正触发修正，而不是只产生一个分数；
- 主要失败模式，包括局部修改破坏全局一致性、复杂关系执行偏差、文字生成错误和验证器与人类偏好的错位。

#### 4.2 Agentic Video and Animation Generation

以62篇视频/动画相关核心论文为主要证据，覆盖脚本到视频、镜头规划、角色与场景一致性、长视频生成、动画控制和音画协同。重点比较：

- 脚本、故事板、镜头、片段、角色和场景的层级状态如何维护；
- Agent 如何分解叙事目标、选择视频/图像/音频工具、安排片段生成并处理跨镜头依赖；
- 时间一致性、身份保持、运动合理性、镜头连贯性和音画同步如何被观察与验证；
- 反馈如何定位错误发生在哪个镜头或时间段，是否支持局部重生成、回滚和预算感知终止；
- 主要瓶颈，包括长程状态漂移、错误跨片段传播、验证成本高和多轮生成的计算开销。

#### 4.3 Agentic 3D, CAD, and World Generation

以18篇3D/CAD/世界生成核心论文为主要证据，覆盖文本到3D、程序化建模、CAD 草图/零件/场景、可交互世界和仿真环境构建。重点比较：

- 几何参数、拓扑、场景图、代码、材质、相机和物理状态如何显式表示；
- Agent 如何选择建模操作、代码/API、生成器、渲染器和仿真器，并在失败后回滚或重构；
- 编译/执行、几何规则、碰撞、物理、可制造性、多视图和交互功能如何提供可执行验证；
- 结构化状态是否支持精确编辑、局部修复和长程依赖保持；
- 主要瓶颈，包括语言计划到几何执行的落差、隐式状态丢失、跨工具接口不一致和真实物理验证不足。

#### 4.4 Agentic Scientific Visualization and Chart Generation

聚焦科学图表、数据可视化和分析型视觉产物，现有核心语料约8篇。重点比较：

- 数据、变量、统计关系、图表类型、坐标轴、图例和研究结论如何共同构成任务状态；
- Agent 如何检索数据、选择可视化编码、生成代码、执行分析并迭代图表；
- 数据忠实性、统计正确性、坐标/单位、可读性、引用和结论一致性如何验证；
- 代码执行、规则检查和渲染检查能否形成比纯视觉评分更可靠的反馈；
- 样本量较小带来的证据限制，以及科学事实错误、误导性编码和不可复现分析等风险。

#### 4.5 Agentic Structured Visual Document and Presentation Generation

聚焦结构化视觉文档、报告、信息图、幻灯片和演示文稿，现有核心语料约8篇。重点比较：

- 内容大纲、章节层级、证据引用、版式、组件和页面间一致性如何表示；
- Agent 如何进行资料检索、内容规划、模板/组件选择、代码或文档工具调用和多页迭代；
- 文本事实、引用完整性、布局溢出、视觉层级、可编辑性、渲染质量和跨页一致性如何验证；
- 是否支持针对单页或单组件的局部修复、版本回滚和用户偏好记忆；
- 主要瓶颈，包括内容正确性与视觉质量的耦合、复杂布局的可控性、端到端评测不足和人工检查依赖。

#### 4.6 Agentic UI and Web Visual Generation

聚焦 UI、网页和可交互视觉界面的生成、重构与迭代。即使当前核心论文数量较少，也应保留该方向，因为它把视觉生成与功能执行直接连接起来。重点比较：

- 页面结构、组件树、交互状态、响应式约束和用户任务如何共同构成状态；
- Agent 如何将自然语言需求转为布局、代码、组件和交互动作，并调用浏览器、渲染器或测试工具；
- DOM/组件检查、截图对比、可访问性、交互测试和端到端任务完成度如何作为验证信号；
- 反馈是否能定位到组件、样式、逻辑或交互状态，并支持局部修复与重新测试；
- 当前证据稀少、基准不统一、视觉相似度与功能正确性脱节等限制。

#### 4.7 Cross-Modal Synthesis: What Changes in the Loop?

在前六节基础上进行横向综合，而不是新增一个与模态章节并列的方法类别。使用“目标—状态—动作—生成器/工具—验证器—反馈—终止—典型失败—证据成熟度”矩阵比较各模态，回答三个问题：

1. 哪些 Agentic 机制跨模态稳定有效，哪些机制依赖特定产物的可执行表示？
2. 哪些模态具有较强的自动验证与回滚接口，哪些模态仍主要依赖主观美学评价？
3. 模态复杂度、长程状态和验证强度是否与自主性等级、成本和可复现性一致变化？

本节应形成跨模态判断：差异的核心不在生成器名称，而在 Agent 可访问的状态、可采取的动作、可验证的约束和失败后的恢复接口。任何跨模态结论都必须标注样本量、论文范围和证据强度，不能用小样本模态代表整个领域。

### 5. Evaluating Whether the Loop Actually Works

本章把“是否生成得好”改写为“闭环是否真正有效”。

#### 5.1 Artifact Quality

整理真实感、美学、清晰度、时间质量、几何质量等传统指标，并明确它们只能评价产物，不足以证明 Agentic 能力。

#### 5.2 Goal and Constraint Satisfaction

评估语义、对象、属性、空间、身份、事实、物理、功能和用户偏好是否满足。强调结果好看不等于任务完成。

#### 5.3 Trajectory and Decision Quality

讨论计划是否可执行、工具选择是否正确、诊断是否准确、反馈是否有效、恢复是否成功、停止是否合理、单位调用带来多少改进。这是当前最缺少统一协议的层级。

#### 5.4 System and Human-Centered Evaluation

比较模型调用数、token/GPU时间、延迟、货币成本、稳定性、可复现性、安全性和人类控制权。对多 Agent、搜索和多轮方法必须讨论等预算比较。

#### 5.5 Evidence Maturity and Evaluation Gaps

结合现有文献的消融、开源、正式发表和PDF核验状态分析证据强度。核心语料中2026年论文97篇，且约93.5%仍以预印本或尚未核验正式venue的形式记录；因此正文应把许多结论表述为“近期预印本初步显示”，而不是领域定论。

### 6. Positions and Research Frontiers

本章不把挑战和未来工作写成清单，而是从前文证据推出若干可辩护的研究立场，每个立场后接可验证的研究方向。

#### 6.1 Position 1: The Field Is Orchestration-Heavy, Not Yet Autonomy-Heavy

以87篇执行编排、83篇L2工具/协作辅助和仅7篇L4长程自主的分布为证据。研究方向是状态依赖控制、失败恢复和动态终止基准。

#### 6.2 Position 2: Verification Is the Bottleneck of Closed-Loop Generation

以生成后验证主导论文稀少、反馈系统常依赖通用评分器为证据。研究方向是将VLM、规则、代码执行、几何/物理仿真和人工审批组合成可校准验证体系。

#### 6.3 Position 3: Long-Horizon Visual Creation Requires Explicit State, Not Longer Prompts

视频、3D和持续编辑暴露出角色、场景、几何、用户偏好和工具轨迹的状态维护问题。研究方向是分层状态表示、可压缩视觉记忆和可回滚的编辑历史。

#### 6.4 Position 4: Evaluation Must Move from Final Outputs to Trajectories Under Budget

研究方向是建立保存状态、行动、反馈、成本和停止过程的基准，并在相同预算下比较单 Agent、多 Agent、搜索和人机协同系统。

#### 6.5 Position 5: Executable Visual Domains Are the Best Testbed for Grounded Agency

CAD、科学图表、文档和UI等任务可通过编译、规则、数据、渲染和功能测试获得更强反馈。研究方向是把这些验证能力迁移到图像与视频的弱监督场景，同时避免把可执行性误当作美学质量。

#### 6.6 Position 6: Self-Improvement Needs Safety and Evidence Before Scale

研究方向是过程奖励、经验质量控制、遗忘与更新策略、跨任务迁移评测，以及对奖励投机、错误记忆和权限边界的安全约束。

### 7. Conclusion

结论只回收三个判断：本文如何用闭环重新界定 Agentic Visual Generation；当前文献最可靠地说明了什么；从工作流编排走向真正视觉 Agent 最需要补齐什么。

建议结论：现有系统已经将规划、工具调用和局部反馈引入视觉创作，但多数仍停留在编排式工作流。可靠验证、状态依赖重规划、自主终止、长程记忆和持续学习是下一阶段的决定性能力。

## 7. 章节内部的统一写法

### 7.1 方法小节模板

第3章的闭环机制小节和第4章的模态小节使用同一套证据逻辑，但分析重点不同。第3章强调 Agent 在闭环阶段承担什么功能；第4章强调视觉产物的性质如何改变这一功能。两类小节都按照以下顺序写：

1. **问题**：该阶段为什么需要 Agent？传统方法失败在哪里？
2. **状态**：系统能够观察到哪些信息？
3. **动作**：Agent 可以采取哪些行动？
4. **方法家族**：现有工作可归纳成哪些机制，而不是有哪些论文名称？
5. **代表证据**：选择少量 P1 论文说明机制和实验结论。
6. **横向比较**：比较不同方法的假设、反馈、成本和适用范围。
7. **局限**：指出失败条件、证据不足和未解决问题。
8. **小结**：回答该类方法在闭环中的真实贡献和成熟度。

第4章的每个模态小节还必须明确交代以下六项：

1. **任务边界与论文覆盖**：说明该小节纳入哪些生成/编辑任务，报告核心论文数量，并区分邻接和支撑工作。
2. **模态特有状态**：说明对象、时间、几何、数据、版式、组件或交互状态如何表示，以及状态是否可持久化。
3. **模态特有验证**：区分主观质量评价、语义检查、规则/代码检查、几何/物理检查和功能测试。
4. **方法家族比较**：至少归纳两类方法机制，并比较它们的反馈来源、控制粒度、成本和自主性等级。
5. **代表结果与反例**：引用少量可回到 PDF 页码的结果，同时保留失败案例或不支持强结论的证据。
6. **模态小结**：回答该模态目前最成熟的闭环环节、最薄弱的环节，以及它对一般 Agentic Visual Generation 的启示。

### 7.2 单个段落的推荐逻辑

推荐使用：

> 主题判断 → 机制解释 → 代表工作证据 → 方法间差异 → 局限或反例 → 本文综合结论

避免以下写法：

> A 提出了……；B 提出了……；C 又提出了……。

这种逐篇罗列无法形成综述自己的观点。

### 7.3 代表论文使用原则

- P1 支柱论文：用于定义方法家族、说明关键机制和支撑主要结论。
- P2 核心覆盖论文：用于证明方法家族覆盖充分、展示变体和补充模态。
- P3 邻接论文：仅用于历史、边界和相邻领域比较。
- 支撑综述：用于概念、评测、安全和方法论，不与核心方法等量统计。

第3章的每个二级机制小节通常选择 2–4 篇 P1 论文详细说明，再用 5–10 篇 P2 论文进行归纳性引用。第4章的每个模态小节可按论文数量调整：图像和视频各选择 4–6 篇 P1 论文作为支柱，3D/CAD、科学图表、结构化文档和 UI/Web 按证据量选择 2–4 篇；其余核心论文用于方法家族覆盖和定量统计。没有必要在正文逐篇介绍全部 168 篇核心论文。

## 8. 术语规范

| 推荐术语 | 使用原则 |
|---|---|
| Agentic Visual Generation | 本文研究领域总称 |
| visual generator | 执行图像、视频、3D 等生成动作的模型，不自动等于 Agent |
| workflow | 控制路径主要由预定义代码决定 |
| agent | 根据观察和状态动态决定后续行动的决策主体 |
| Agent-augmented workflow | 包含 Agent 模块，但总体控制流仍较固定 |
| closed loop | 输出被重新观察，反馈实质性改变后续行动 |
| iteration | 仅表示重复，不能自动等同于闭环自主 |
| multi-agent | 存在多个角色或决策主体，不能自动等同于高自主性 |
| verifier | 检查明确约束是否满足，应与一般美学 critic 区分 |
| self-improvement | 策略、技能、记忆或模型跨任务发生持续变化，不只是当前任务重试 |

正文、分类表和图表统一使用 L1–L5；已有核心方法主要分布在 L2–L5，L1 作为固定映射或固定流程基线。重点 roadmap 使用相同编号讨论视觉能力演进，引用时必须写出其阶段名称，不能直接等同于本文的控制与证据等级。

## 9. 证据与引用规范

### 9.1 必须回到 PDF 核验的内容

1. 作者和单位。
2. 数据集规模和划分。
3. 主要指标和具体数字。
4. 与基线的提升幅度。
5. 消融实验结论。
6. Agent 的控制流、反馈和停止机制。
7. 作者明确承认的局限性。
8. 是否开源代码、模型和数据。

### 9.2 结论措辞与证据强度

- 多篇独立、同行评审工作一致支持：可写“现有证据普遍表明”。
- 主要来自少数预印本：写“近期工作初步显示”。
- 仅有案例或封闭系统观察：写“案例表明可能”或“从外部行为推测”。
- 没有直接实验比较：不能写“显著优于”“证明了”或“解决了”。
